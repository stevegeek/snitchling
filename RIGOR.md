## Notes

This project is completely vibe coded.

The idea was mine: the stock OpenSnitch UI was using far too much memory, so
replace it with something small that talks to the same daemon. Everything
after that, the plan, the protocol research, the Rust implementation, the
tests and these docs, was done by an AI (Claude Code) in a single session. I
approved the plan, and I have run the result, but I have not read the code.

- **comprehended: no**: no human has read the code line by line.
- **quality_reviewed / security_reviewed: no**: there was no deliberate review
  pass, by a human or an AI, beyond the compiler and clippy. Bear in mind this
  is the UI of a firewall: the answers it sends decide what may connect.
- **tested: ai**: the AI wrote and ran unit tests for rule building and
  integration tests that play the daemon over a real unix socket, then checked
  the binary against a real `opensnitchd` 1.7.2: every rule command (add,
  disable, enable, edit, delete), a denied connection being blocked and an
  allowed one going through. Testing against the real daemon found a bug the
  tests had missed (see the vendored `h2` patch in the README).
